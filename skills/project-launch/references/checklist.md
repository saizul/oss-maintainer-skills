# Launch readiness checklist

## The project

- [ ] The quick start works on a clean machine (fresh container or VM), copy-pasted
      from the README, in under 5 minutes
- [ ] Installable from the ecosystem's registry (PyPI, npm, Packagist, crates.io,
      Homebrew, Docker), not only from a git clone
- [ ] A tagged release with release notes exists
- [ ] Known rough edges are documented honestly (status: alpha/beta/stable)
- [ ] Error messages for the most common mistakes are helpful

## The repository

- [ ] README: one-line pitch, badges, quick start, demo image or GIF, FAQ
      (`readme-writer` lint passes)
- [ ] LICENSE, CONTRIBUTING.md, CODE_OF_CONDUCT.md, SECURITY.md present
      (`repo-health-check` score 80+)
- [ ] CI is green and the badge shows it
- [ ] 5-10 open `good first issue` issues so excited visitors can help immediately
- [ ] Repository description (one sentence) and 5-10 topics set on GitHub
- [ ] Website/homepage field set (docs or demo)
- [ ] Social preview image uploaded (Settings > General, 1280x640) so links unfurl well
- [ ] Discussions enabled if you want questions out of the issue tracker

## The maintainer

- [ ] You have a few hours free right after each post to answer comments
- [ ] Drafts written in your own words, with the real story and trade-offs
- [ ] A list of likely critical questions and honest answers
      ("why not X?", "is this production ready?", "what about Windows?")
- [ ] Analytics expectations set: most traffic arrives in the first 24-48 hours

## Don'ts

- Do not ask anyone to upvote, star or comment. Share the link, not a request for votes.
- Do not post the same text to many subreddits on the same day.
- Do not argue with critics; thank them, answer the technical point, move on.
- Do not buy stars, followers or "launch services".
